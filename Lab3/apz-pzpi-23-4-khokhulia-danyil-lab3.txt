ЗАВДАННЯ
     На цій лабораторній роботі потрібно розробити front-end частину програмної системи. Ця частина системи повинна підтримувати роботу клієнтів у веб-режимі та забезпечувати адміністрування системи, тобто мати окремий інтерфейс для звичайних користувачів і окремий — для адміністраторів (відповідно до ролей користувачів вашої системи). Користувацький інтерфейс та інтерфейс адміністрування повинні підтримувати інтернаціоналізацію та локалізацію, а саме, забезпечувати: підтримку української на англійської мов сайту, формат дати та часу відповідний регіону, порядок сортування текстових значень, різні напрями введення тексту тощо. Адміністрування системи повинно забезпечувати: управління користувачами системи, управління даними системи, створення резервних копій налаштувань та даних, експорт та імпорт даних та налаштувань.

ОПИС ВИКОНАНОЇ РОБОТИ
     Під час виконання лабораторної роботи було вирішено завдання проєктування та реалізації веб застосунку для системи автоматизованого управління мережею пралень WashConnect. Розробка зосередилася на побудові повнофункціонального SPA , який забезпечує окремі інтерфейси для звичайних клієнтів пралень та системних адміністраторів. Розробка велася мовою TypeScript із використанням бібліотеки React 18, збирача Vite, бібліотеки управління глобальним станом Zustand, інструменту для синхронізації серверного стану TanStack React Query та фреймворку інтернаціоналізації i18next. Це дозволило забезпечити реактивний інтерфейс із підтримкою української та англійської мов, а також дотриманням принципів Clean Architecture.
     3.1 Архітектура веб-застосунку
     Архітектура застосунку побудована за багатошаровим компонентним принципом із розмежуванням відповідальності, де структурно проєкт складається з декількох логічних шарів. Шар презентації (Presentation Layer) реалізований за допомогою React та містить сторінки: Home, Login, Register, Laundries, LaundryDetail, ActiveSession, Wallet, Profile та AdminDashboard. Навігація між сторінками здійснюється через React Router DOM. Компонент Layout забезпечує єдину точку рендерингу навігаційної панелі, яка змінює свій вигляд залежно від статусу авторизації та ролі користувача. Сторінки адміністратора захищені спеціальним компонентом ProtectedRoute.
     Шар управління станом (State Layer) поділений на дві незалежні частини. Локальний стан автентифікації та налаштувань зберігається за допомогою Zustand із middleware persist. Серверний стан, який включає списки пральних машин та історію сесій, керується через TanStack Query, що забезпечує автоматичне кешування, дедублікацію запитів та фонове оновлення даних.
     Шар сервісів (Service Layer) побудований на базі axios із централізованою конфігурацією. Інтерсептор запитів автоматично додає JWT-токен із Zustand-стору до заголовка авторизації перед відправленням кожного мережевого запиту до бекенду.
     Шар інтернаціоналізації (i18n Layer) побудований на бібліотеці react-i18next і підтримує українську та англійську мови. Конфігураційні файли містять переклади всіх елементів інтерфейсу, від назв кнопок до статусів замовлень та сповіщень. Форматування дат і часу здійснюється автоматично з урахуванням обраної локалі та регіону користувача
  3.2 Реалізація клієнтського інтерфейсу
  Після реєстрації та авторизації клієнт отримує доступ до каталогу пралень, який завантажується через API та відображається у вигляді інтерактивних карток на сторінці Laundries. Перейшовши на сторінку LaundryDetail, клієнт бачить деталі обраної пральні. Він може вибрати вільну пральну машину, обрати необхідний режим прання та вказати точний час бронювання через спеціальне поле вводу дати та часу. Гроші автоматично списуються з балансу клієнта безпосередньо у момент оформлення бронювання.
  Сторінка ActiveSession забезпечує інтерактивне керування процесом прання. Якщо статус сесії позначений як заброньований, користувачу доступна кнопка початку прання, яка ініціює виклик API для блокування дверцят та переведення статусу машини в активний. Під час активного прання клієнт бачить зворотний відлік часу та має можливість поставити процес на паузу, продовжити його або виконати екстрене скасування. Окрім цього, сторінка Wallet дозволяє клієнту переглядати баланс, історію транзакцій, поповнювати рахунок та застосовувати промокоди через відповідні мутації.
  3.3 Реалізація адміністративної панелі 
  Адміністративна панель доступна виключно для користувачів із роллю Admin і забезпечує системне управління додатком. Управління користувачами реалізовано у вигляді таблиці з можливостями швидкого блокування або розблокування клієнтів, а також зміни їхніх ролей в системі.
  Управління даними реалізовано через окремий модуль Data Management, який дозволяє адміністратору експортувати всі системні налаштування та дані у файл формату JSON для створення безпечних резервних копій. Також передбачено функціонал імпорту даних із раніше збереженого JSON-файлу, що забезпечує швидке відновлення всієї системи у разі збоїв та відповідає вимогам щодо керування налаштуваннями додатку.
     3.4 Підсистема інтернаціоналізації та локалізації
     Підтримка двох мов інтегрована на рівні всього додатку. Статичний контент інтерфейсу повністю перекладається через функцію бібліотеки i18next. Зміна мови відбувається миттєво без необхідності перезавантаження сторінки і зберігається у локальному сховищі браузера для майбутніх сесій. Дати та валютні значення завжди форматуються відповідно до обраної мови та стандартів регіону.
     
     
     3.5 UML-діаграми веб-застосунку
     3.5.1 Діаграма прецедентів
     Побудована діаграма прецедентів відображає загальний перелік функціональних можливостей системи. Визначено двох основних акторів, якими є Клієнт та Адміністратор. Функціонал Клієнта охоплює безпечну авторизацію, бронювання пральної машини на визначений час, управління сесією прання та її оплату. Адміністратор володіє розширеними правами для управління системою, генерації резервних копій через експорт та імпорт JSON-даних і модерації користувачів.

Рисунок 1 – UML діаграма прецедентів


     3.5.2 Діаграма компонентів
     Діаграма компонентів наочно візуалізує загальну структуру клієнтської частини. Застосунок чітко розділений на рівень презентації, рівень стану та рівень сервісів. Взаємодія з бекендом на базі C# ASP.NET Core відбувається за стандартним протоколом HTTP REST, що гарантує повну незалежність клієнтської частини додатку від сервера.

Рисунок 2 – UML діаграма компонентів
     3.5.3 Діаграма діяльності 
     Діаграма діяльності детально моделює бізнес-процес бронювання та запуску прання. Спочатку клієнт послідовно вибирає потрібну машину, режим і зручний час. Потім система перевіряє його баланс і при достатній кількості коштів успішно створює бронювання. Далі клієнт ініціює старт прання, що активує зворотний таймер. Цей процес також може бути призупинений користувачем за потреби.
 

Рисунки 3-5 – UML діаграма діяльності
     3.5.4 Діаграма огляду взаємодії 
     Діаграма огляду взаємодії Діаграма візуалізує комунікацію між React-клієнтом та сервером під час життєвого циклу прання. Серверна частина виконує роль головного джерела істини, яке відповідає за списання коштів та зміну статусу. Водночас клієнт синхронізує свій UI з сервером через запити, реактивно реагуючи на дії користувача під час натискання кнопок паузи або старту.
